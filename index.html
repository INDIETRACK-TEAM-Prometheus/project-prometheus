          Provisional frozen-scene gaze search · local QA

          With separate consent and after an independent calibration passes, the canvas frame is frozen. Samples are collected for 1.5 s, the latest valid webcam gaze point is chosen and SAM is called automatically. A sample counts only if its browser capture estimate is within 250 ms of the processing callback and the callback within 100 ms. That is a software freshness limit; physical camera and display timing error is not measured. Do not use it as causal / online alignment, T15 or a gate pass.

          Checking the compute profile

          Not set · model default (24-inch 16:9)

          After calibration, clicking the live scene treats the clicked point as where you were looking and sends two camera frames from that moment to the remote GPU to correct this session gaze model (WebEyeTrack click calibration). The correction is not saved and is not independently checked.

          The cloud profile opens the camera in the browser and sends JPEG frames of 640 px or less, at most 12 per second, through this device loopback proxy to the remote GPU. The browser sends no eye crops or facial landmarks. The GPU processes frames in memory and keeps only derived gaze results from calibration in session RAM for up to 10 minutes; raw frames and eye patches are never written to disk or logs. A passed calibration saves only the gaze MLP model-only adapter and the calibration affine (2×3 numbers) in this device IndexedDB. Rendering and local video recording stay on this device. If the cloud GPU is not ready, start is blocked and there is no fallback to a local model.
