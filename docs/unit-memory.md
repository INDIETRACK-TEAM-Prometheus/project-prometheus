# Memory unit implementation and limits

`src/memory/index.js` is an isolated in-memory research prototype; it is not connected to the application or the older `src/core.js` implementation. EvidenceRing keeps a bounded recent ring separate from event pins. Pins count unique evidence bytes, fail explicitly on unavailable evidence or capacity, and record expiry/deletion reasons. Caller-supplied byte counts must describe the actual representation. Time is monotonic milliseconds. ExperienceMemory stores cloned event/observation records, temporal relations, reversible identity links and derivation validity. A delayed event revision retains observed time and identifies its predecessor. Last-seen output is explicitly not a current position. Deletion suppresses affected retrieval and invalidates registered derivations. Callers must explicitly propagate deletion to both the ring and memory and to any external cache or index.

`causalReplay` accepts already normalized records; it is **not an Aria dataset loader**. It filters by observed and processed time and explicit online causal status, removes the named evaluation fields and provides null/reason for missing fields. This is not a general information-flow security boundary: callers must whitelist and validate dataset schemas and provenance before use.

`MemoryService.open({sessionId})` defaults to ephemeral storage. Its async `ingestFrame`, `ingestEvent`, `advanceTime`, `reviseEvent`, `observe`, `addDerivation`, `addRelation`, `link`, `unlink`, `retrieve`, `deleteEvidence`, `deleteSession` and `close` operations serialize mutations. Event pinning and the memory update are saved together in one session snapshot; storage failure rolls back the in-process change. The default snapshot quota is 1 GiB of JSON-encoded state and the default record limit is 10,000, including eviction metadata and tombstones. Both are configurable; quota overflow rejects the entire mutation rather than silently discarding history. These limits do not measure any external files and are not a browser allocation or whole-device storage guarantee. `advanceTime` must be called by the host as monotonic time advances to enforce ring and pin age when no input is arriving. Evictions mark events and invalidate registered derivations; retrieval shows the latest applicable event revision.

Evidence IDs appearing in eviction records cannot be ingested again in the same session; use a new ID for new evidence. This also applies when a shared pin is evicted and another pin still holds that ID. Historical eviction records are retained, and deletion tombstones remain separate.

`IndexedDBStorage` is optional, and enabling a durable storage adapter requires `retentionConsent: true` and a positive numeric `retentionMs`. IndexedDB writes a whole snapshot in one transaction; reopening restores the snapshot and expired snapshots are deleted when opened. Retention uses a single injectable wall `clock`, distinct from the caller-supplied monotonic evidence timestamps. `deleteSession` deletes the snapshot, while closing a durable session retains it. This implementation assumes one writer per session; cross-tab ownership and concurrent writer conflict detection are not implemented. An expired session is inaccessible from the service, but expiry cleanup is only performed on reopening: background retention enforcement is not implemented. There is no user-facing consent flow, encryption, or external index/cache deletion. The ring's byte limits rely on truthful caller-supplied sizes. Browser IndexedDB, abrupt process termination, real quota behavior, and retention under browser eviction have not been verified; storage mock tests are not evidence of those behaviors.

Synthetic unit tests in `test/memory.test.js` exercise parts of T05, T06, T07, T16, T17, T20 and T21, including snapshot reopen and simulated storage failure. These are not acceptance or Gate passes. No measured retrieval Recall@K or location/time error, actual gaze/frame data, map correction transformation, real Aria dataset, real causal provenance validation, integrated cache invalidation, or live system is demonstrated. In particular T17 map correction versus object motion remains unimplemented. OPS durable recovery and deletion propagation beyond this service remain **blocked/not verified**; in-memory idempotency and mocked reopen do not establish crash recovery. Integration and end-to-end acceptance remain outstanding.
