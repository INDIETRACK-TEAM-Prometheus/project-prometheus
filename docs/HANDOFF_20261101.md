## 실행·종료 명령

기존 4173 서버가 있으면 그 터미널에서 Ctrl+C로 종료한다. **아래는 인수자가 필요할 때 실행하는 명령이며 문서 작성으로 GPU가 시작되지는 않는다.**

```powershell
cd "C:\Users\ngoch\OneDrive\바탕 화면\Project_Prometheus\Prometheus_Implementation_Checkpoint_v0.1\prometheus"
$env:META_API_KEY = [Environment]::GetEnvironmentVariable('META_API_KEY', 'User')
$env:PROMETHEUS_HTTPS_CERT = Join-Path $env:LOCALAPPDATA 'Prometheus\https\localhost-cert.pem'
$env:PROMETHEUS_HTTPS_KEY = Join-Path $env:LOCALAPPDATA 'Prometheus\https\localhost-key.pem'
.\scripts\colab\start-system.ps1 -Gpu T4 -RunServer
```

`Prometheus: https://...`가 나온 뒤 `https://127.0.0.1:4173` → Ctrl+Shift+R → ▶ 시작 → 교정. 환경변수에 경로를 넣는 것은 인증서를 생성하지 않는다. `ENOENT`면 먼저 인증서 파일 존재와 README의 HTTPS 준비 절차를 확인한다.

Colab VM은 실행 중 과금된다. `-RunServer`는 Node 종료/시작 실패 시 finally 정리를 시도한다. Ctrl+C 후 정리 결과를 확인한다. 실패하거나 다음 실행에서 managed state 오류가 나면:

```powershell
.\scripts\colab\stop-system.ps1
# 출력에 지정된 세션으로 복구가 필요하면:
# .\scripts\colab\stop-system.ps1 -Session <실제-관리-세션명>
```

CLI 경로: `%USERPROFILE%\.prometheus\bin\colab.exe`; 도구 환경: `%USERPROFILE%\.prometheus\uv-tools`. `uv trampoline failed to canonicalize script path`이면 `.\scripts\colab\setup-colab.ps1`로 고정 버전 0.7.5 재설치. 인증·GPU 생성은 이 설치 명령에 포함되지 않는다. 예전 `.local\bin\colab.exe`나 Codex MSIX 내부 uv 경로에 의존하지 않는다.

SSH 키/관리 상태: `%LOCALAPPDATA%\Prometheus\colab` (키 값을 읽거나 출력하지 않는다). 관리 PID와 포트 매핑을 확인하는 종료 스크립트를 사용하고, 기록 파일을 지워 실행 중 VM을 고아 상태로 만들지 않는다. 이름이 다른 사용자 VM이나 모든 node/ssh 프로세스를 일괄 종료하지 않는다.

## 로그와 재현에 필요한 자료

- 서버 단계 로그: `data/diagnostics/calibration-stages.jsonl` + 회전 파일, 파일당256KiB 상한. 같은 Origin/loopback에서 허용한 단계·시간·표본 수·세션 UUID만 기록한다. 서버 재시작 전 과거 브라우저 로그는 소급 생성되지 않는다.
