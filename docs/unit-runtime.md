# Runtime unit scope and evidence

**2026-11-01 consistency note:** the first paragraphs describe the unit at creation (2026-10-27). Since then `RuntimeFacade` also accepts a `server_provider` analyzer (`src/runtime/server-providers.js` → `/api/analyze`), which calls actual `sam-3.1` and the user-approved `muse-spark-1.3` (SRS 20.8; Wonder remains unavailable). `src/runtime/background-attention.js` and `background-browser.js` add the continuous 1-second background coordinator (one in flight, one latest pending) used by the app. Live calls are recorded in `evidence/perception-live.json` and `reasoner-live-v*.json`. Current Gate status is in `CTO_REVIEW.md`; G0 and G4 remain not passed. The text below is retained as the original unit record.

Internal, isolated building blocks only; no actual SAM 3.1 or Muse Wonder provider endpoint, model identity, authentication, input/output schema, license, price, or access is known here. Both capabilities are explicitly blocked. No substitute provider or real call is made. G0 and G4 are not passed.

`node --test test/runtime.test.js` uses synthetic fixtures. T09 covers one active request, one latest pending request, stale completion, stop, and timeout. It does not establish 30-minute behavior, duplicate-event persistence, retries, rate/cost limits, circuit breaking, or full session integration. T10/T18 cover explicit map, object, identity, evidence and expiry dependencies; the producer must correctly declare every dependency. T15 exercises a calibrated linear clock model, jump flag and conservative total alignment budget; real calibration, jump detection, physical display timing, pose interpolation and live streams remain unverified. T19 checks up to five free-form scenarios including abstention via an empty list; it does not run a model or evaluate action accuracy. T22 checks blocked status; no external-action capability is implemented here. Keeping text as a string is not evidence of prompt-injection resistance for a future provider adapter.

The contract validators are a deliberately narrow internal subset, not comprehensive JSON Schemas for all record types. Actual per-record schema coverage, durable idempotency, API security boundaries, full integration, and acceptance tests remain outstanding. Nanosecond timestamps represented as JavaScript numbers can lose integer precision at large values; callers must supply a safe session-relative representation or use a future exact integer contract.

`RuntimeFacade` wires trusted local fixture functions to bounded scheduling, scenario validation, a dependency cache and optional synchronous event append. It rejects unspecified or non-fixture providers and reports actual SAM/Wonder as blocked. Fixture code is trusted injected code: the `kind` label is not a network sandbox or a verified provider. Input contracts strictly allow only frame fields `frameId, observedAt, processedAt, imageData, sceneText`, gaze `x, y, observedAt, processedAt`, event `eventId, observedAt, processedAt`, and context `{memory:[{evidenceId,text,observedAt,processedAt,causalStatus}]}`. Times share the configured clock domain; each observation must not exceed the frame observed time and processing must fall between observation and current time. Memories require `online_causal`. Dependencies specify map identity, object IDs, input evidence IDs and expiry; scenario grounding must reference those input evidence IDs. Unknown fields are rejected, including nested hidden state. This structural boundary cannot prove that a caller has labeled data truthfully or that unstructured image/text content is causal, private, or free of instructions; those require trustworthy sources and an isolated provider integration. No automatic action execution or network operation is present.

`node --test test/runtime*.test.js` exercises fixtures, including in-flight invalidation, event suppression, budgets and stop/restart. Cache is bounded to 256 entries and expired entries are pruned on submission; event deduplication keeps at most 1024 IDs, so eviction permits later duplicates. Both are in-memory only. Synchronous store failure is surfaced as `store_failed_partial_possible` without publishing a prepared result, but earlier writes may already have happened; true atomicity and durable idempotency remain unimplemented. Publish failure is surfaced as `publish_failed` and a cached result can remain. Fixture cost is a configured estimate, not provider billing. Timeout aborts the signal but keeps the concurrency slot until a noncooperative function settles; permanently hung functions need a worker/process boundary for recovery. No external integration, performance, or real-provider gate is passed.

The perception pipeline invalidates dependent results when a linked object's image bounds change or a new association is ambiguous. Image-space change is a conservative observation conflict, not proof of physical motion; unchanged and unrelated observations retain cached results. Actual object motion and identity performance remain unverified.
