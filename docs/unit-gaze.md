# Gaze unit: scope and evidence

`src/gaze/index.js` is a dependency-free set of primitives; it does not open a camera, load a model, or process a frame on import. `src/gaze/webcam.js` provides an injectable browser controller for MediaPipe Face Landmarker, but its module, WASM and model assets are not bundled. Actual browser/model integration and G1 remain **blocked**, not passed. The earlier generic `createLandmarkSession` boundary is also available for other injected providers; neither wrapper guards camera acquisition performed by unrelated application code.

## Browser controller contract

`createWebcamGazeController({video, mediaDevices, loadVision, wasmRoot, modelAssetPath, onSample, onError, blinkThreshold})` takes an unmirrored HTML video, `navigator.mediaDevices`, a function that imports `@mediapipe/tasks-vision`, and explicit compatible WASM root and Face Landmarker model asset paths. A locally hosted version-pinned module/WASM/model is recommended; these paths can be remote only with appropriate disclosure and consent. No URL, dependency, model or key is silently supplied. The official package/model instructions are at https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/web_js and landmark topology at https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/face_landmarker/face_landmarks_connections.ts . Model and runtime licenses, versions, provenance and access should be verified by the integrator.

Only after a user action and consent call `await controller.start({userInitiated:true,cameraConsent:true,videoConstraints:true})`; then runtime and model load followed by `getUserMedia`, with audio disabled. No fallback device is silently attempted on permission failure. Secure context, user permission and `requestVideoFrameCallback` are required. Returned `{width,height,frameRate,deviceId}` are track settings, not measured FPS. `stop()` cancels callbacks, closes the model and stops tracks, including a stream that arrives after cancellation. The controller's state guards its own access, not other code.

`onSample` receives `{timestampMs,timestampKind,processedMs,faceDetected,leftEye,rightEye,features,rawScreenXY,valid,invalidReason,width,height}`. The anatomical eyes expose source-pixel corner and iris landmarks, corner-anchored `crop`, blink score, and `confidence:null` (the provider does not supply calibrated eye confidence). The four features are iris x/y relative to each eye's corner midpoint and corner distance. During calibration collect these real features with unique IDs and known screen-pixel targets, call `fitCalibration`, then `controller.setCalibration(model)`; collect separate validation samples and use `calibrationMetrics`. Prior to calibration or during detected blink/face loss, gaze is null. Blink threshold is an unvalidated engineering default; occlusion, glasses, lighting and head-movement degradation are not reliably detected. This should not be treated as acceptance-quality gaze without independent validation and quality gating. `stop()` clears calibration. Apply display mirroring to both image and overlays only, not model input.

`timestampKind` identifies a browser-provided capture estimate when available; otherwise it explicitly reports callback time, not a measured capture time. `processedMs` is the callback time, not the inference completion time. No frame/scene alignment or clock synchronization is performed. Inference is synchronous and can block the UI; the official guide recommends a worker for this. No video or model frame is persisted or transmitted by the controller itself, but remote asset fetches and any integrator behavior need separate review.

Every sample currently sets `syncUncertaintyMs:null` and `sceneAssociationEligible:false`, including browser capture estimates: neither a clock calibration nor a bounded capture/display uncertainty has been established. Do not send these timestamps into a scene association as precise capture times. The regression stores per-feature training minima/maxima; the controller withholds gaze outside this bounding box. Being inside the box does not establish convex-hull inclusion, quality or accuracy. Out-of-frame landmark coordinates and incomplete iris points are rejected. The blink threshold, inferred eye landmarks and this guard do not establish pupil visibility or detect head-pose drift, reflections and lighting deterioration; those are engineering omissions and require conservative quality gating and recalibration. Calibration validation must be performed separately before using any output.

## Optional asset preparation

`bash src/gaze/setup-assets.sh` is an explicit, optional network/download action, not run by the application. It pins npm package `@mediapipe/tasks-vision` 0.10.21 from the official npm registry and Google Face Landmarker float16 model revision 1 at the URL published in [Google's sample](https://github.com/google-ai-edge/mediapipe-samples-web/blob/main/src/tasks/face-landmarker.ts). It requires `MEDIAPIPE_TGZ_SHA256` and `FACE_MODEL_SHA256` as independently verified 64-hex SHA-256 values before making any request; both archives are checked before extraction. No authoritative checksum has been verified in this environment, so values are intentionally not invented or auto-trusted. Acquiring trustworthy checksums and actual artifacts is blocked here by network restrictions. A failed setup leaves its directory for inspection and refuses to overwrite it on retry.

After successful setup, serve the files same-origin, without exposing directory listing: `src/gaze/assets-0.10.21/package/vision_bundle.mjs`, `src/gaze/assets-0.10.21/package/wasm/` (including its WASM and JS files), and `src/gaze/assets-0.10.21/face_landmarker.task`. Example URL mapping under `/src/gaze/assets-0.10.21/` requires the server to serve `.mjs` as JavaScript and `.wasm` as `application/wasm` and retain the package's WASM filenames. Import the module dynamically only inside `loadVision`, use that wasm directory as `wasmRoot`, and use the model path for `modelAssetPath`. Verify package contents and license before use. Availability and exact server MIME/routing have not been tested. This setup cannot substitute for camera permission, real-provider smoke test or the human validation gate.

Calibration fits an affine least-squares mapping from selected feature vectors to screen CSS pixels; iris/eye features and optional head-pose correction features must be chosen and validated by the integrator. Head pose is only for correction, never an intent signal. Samples require unique IDs. Training and independent validation metrics are separate, and validation rejects reused training sample IDs; the caller must also enforce independent targets/trials and participant/scene separation. `valid:false` attempts remain in the denominator. Metrics are p50/p95 Euclidean error divided by the screen diagonal and valid fraction; no automatic pilot pass is claimed. SRS 20.5 requires 9 independent targets × 3 trials per user, ≥80% valid and p95 ≤5%, with glasses, illumination and distance recorded; this unit cannot establish those conditions.

Coordinate mapping takes current screen and app rectangles in the same CSS-pixel screen coordinate system, and a world viewport rectangle relative to the app. The caller must obtain trustworthy geometry and refresh it on move, resize, zoom, display scale or screen change; recalibrate when required. Non-world points have null viewport coordinates. The browser may not reliably expose all physical-display geometry; do not infer it silently. Mirroring is display-only; apply the same transformation to the displayed image and landmarks, preserving anatomical left/right labels. Eye crops are anchored to two eye corners, not the iris, clipped to the frame; callers must preserve anatomical labels and render the actual image.

Tracking records the current timestamp and invalidates rather than reusing old positions when a face/eye is lost, blinking, degraded, uncalibrated or unavailable. Detection of lighting, glasses reflection and head movement requires real provider/quality logic and is not implemented here. Raw versus display smoothing is not implemented; no raw timestamp is overwritten. Per-eye confidence is passed through, not calibrated. This unit has no clock synchronization, scene frame association, capture timestamp source, device ID/FPS measurement or display uncertainty: SYNC-01–03 and EYE-01 remain integration work. T01 and T15 are not passed. No actual camera or person data was evaluated; synthetic tests establish only computational behavior.

Run `node --test test/gaze*.test.js`. Before G1 acceptance, integrate consent-controlled camera and real landmark provider, eye UI and dynamic scene, measure actual sampling and independent-person calibration, test changes in geometry and tracking quality, and report failures and environment. Never label synthetic tests as G1 or pilot acceptance.
