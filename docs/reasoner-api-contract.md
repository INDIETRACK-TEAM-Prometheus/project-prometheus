# Meta Spark reasoner contract and verification

**2026-11-01 consistency note:** three values below were written before later changes. Current `server/reasoner-adapter.js` uses `max_output_tokens: 4096` (raised after two incomplete provisional calls at 2048; see CTO_REVIEW 2026-10-30). The explicit `store:false` request was exercised live in `evidence/store-false-live.json` (accepted; follow-up GET 404, which is not proof of zero retention). The shared estimated budget is $1/minute by default, configurable with `PROMETHEUS_PROVIDER_BUDGET_PER_MINUTE` (changed in `bd1d810` for the background loop), not $0.10/minute. The original text is kept as history.

The server adapter requests Meta Model API `POST https://api.meta.ai/v1/responses`, using `muse-spark-1.3` (Standard) at minimal reasoning effort by default (`PROMETHEUS_SPARK_MODEL` / `PROMETHEUS_SPARK_EFFORT` override it; measured 2026-11-03 on a real Aria frame: 1.3 minimal 4.6–5.3 s, 1.3 low 8.1–8.7 s, 1.1 low 3.7–4.1 s but descriptive rather than predictive), a 4096 output-token cap, and an explicit `store: false` request; the latter is unit-tested but not yet verified by a new live call. It requests strict JSON Schema output and no tools. It validates the returned model, at most five scenarios and their evidence references. Inputs are allowlisted, causal-labelled synthetic or sensor observations with time cutoffs; the label is a caller assertion, not proof of causal provenance. The model receives text as untrusted data; prompt-injection resistance is not established.

`node scripts/verify-reasoner-live.js` sends a synthetic image and gaze through the actual local `/api/analyze` pipeline to SAM 3.1 and Spark. The report `docs/evidence/reasoner-live.json` records fixed success criteria before dispatch and sanitized response metadata and scenarios. A successful call demonstrates this integration sample only, not predictive accuracy, real-world tracking, or product acceptance. The report requires both returned model identities and valid grounding; an empty scenario list is an allowed abstention.

The previous Wonder evidence remains under `docs/evidence/wonder-live.json`; Spark is a user-authorized alternative, not a claim of Muse Wonder access or equivalence. Provider requests use a shared bounded policy, with no automatic retry. The timeout is 60 seconds and response bodies are capped at 256 KiB. See Meta's [Responses protocol](https://dev.meta.ai/docs/protocols/responses) and [structured output](https://dev.meta.ai/docs/structured-output).

The reasoner can receive the same validated PNG/JPEG data URL as an image content item alongside the JSON evidence in the same request. This occurs only on the explicitly authorized remote path. The v2 synthetic probe records its results separately in `docs/evidence/reasoner-live-v2.json` and records whether any scenario was generated; abstention remains a valid response.

The adapter limits serialized evidence to 16 KiB and reserves $0.05 per Spark attempt within the shared $0.10/minute estimated budget; SAM separately reserves $0.0025. These reservations are throttling estimates, not a hard spending guarantee: image tokenization and actual billing are unknown until provider usage arrives. The response includes bounded input/output and cached-input token counts when supplied. If all three are available, `estimatedCostUsd` applies the published Standard rates of $1.25 uncached input, $0.15 cached input and $4.25 output per million tokens. Missing or invalid usage yields a null estimate. Rates and account billing can change; the calculation is not an invoice. [Meta pricing](https://dev.meta.ai/docs/pricing-rate-limits).

## Provider retention and image limits (2026-10-28)

Meta documents [Responses](https://dev.meta.ai/docs/protocols/responses) as defaulting to `store: true`. The adapter now explicitly requests `store: false`; this is not zero data retention and does not delete responses from previous calls. [Standard Services terms](https://dev.meta.ai/legal/terms-of-service) state request content is not used to train Meta models and separately allow retention for listed purposes. [ZDR](https://dev.meta.ai/help/policies-and-privacy/zero-data-retention) requires separate organization enablement and may vary by model; account eligibility, actual retention periods, and applicable agreement remain unverified. [Image understanding](https://dev.meta.ai/docs/image-understanding) publishes a 50,000,000-byte inline image limit and up to 50 images per request for Spark; this application uses one PNG/JPEG under its stricter 8 MiB local JSON limit. These Spark figures do not establish SAM-specific size limits.
