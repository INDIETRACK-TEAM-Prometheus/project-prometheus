## Findings and smallest follow-up

1. **Stored-response behavior and retention remain unverified for this account.** Meta documents Responses `store: true` as the default. Both current adapters omit `store` in the request, so the documented default should be assumed for Spark; SAM uses the same endpoint but its effective behavior has not been independently verified. This is material to the consent description. `store: false` is a possible minimization change, but it does not prove zero retention for abuse, legal, security, or other processing, and existing stored responses are not automatically removed. Meta's Standard terms state content is not used to train Meta models, while separately allowing retention for listed purposes. Zero Data Retention is separately enabled for eligible organizations, is not a Standard default, can vary by model, and has exceptions. **Follow-up:** record the applicable account/organization terms, actual retention and support-confirmed SAM/Spark behavior; decide whether to request `store: false` and disclose the resulting policy. Do not represent ZDR or deletion as established. [Responses](https://dev.meta.ai/docs/protocols/responses); [Model API terms §§4.4–5.1](https://dev.meta.ai/legal/terms-of-service); [ZDR help](https://dev.meta.ai/help/policies-and-privacy/zero-data-retention).

2. **Image and payload limits: general published facts are available, SAM-specific ceiling remains open.** Meta's Spark image-understanding page lists inline image limit 50,000,000 bytes per image, up to 50 images per request, and JPEG/JPG, PNG, GIF, WebP and ICO MIME types. The generic file-handling page also states a 50 MB inline limit. SAM's segmentation page describes shared Responses requests and image/video inputs but does not state an explicit SAM still-image byte or dimension ceiling. Do not promote the Spark figure or the generic inline figure to a verified SAM-specific limit without confirmation. The implementation accepts PNG/JPEG data URLs, caps the local JSON body at 8 MiB and SAM output source axes at 4096; these are implementation limits, not Meta guarantees. **Follow-up:** add the public Spark/general limits with their scope and keep SAM-specific input-byte/dimension limits TBD until Meta documentation or support confirms them. [Image understanding](https://dev.meta.ai/docs/image-understanding); [File handling](https://dev.meta.ai/docs/file-handling); [SAM segmentation](https://dev.meta.ai/docs/sam/segmenting).

3. **Public rate limits versus effective team allocation.** The pricing page lists per-team `sam-3.1` 3,000 RPM and no TPM; Standard `muse-spark-1.3` 3,000 RPM and 4,000,000 TPM. It lists numeric request/token limit and remaining headers on successful token-based responses, but does not promise those headers on SAM requests. The current adapters do not record rate headers and existing evidence does not establish this account's effective limits. Local request, cost and in-flight limits remain independent of the provider's published limits. **Follow-up:** on the next already-authorized normal Spark request, optionally record only bounded numeric values from the four documented `x-ratelimit-*` request/token headers, their presence and capture time; omit every other header and all credentials. This is an observational current-window sample, not proof of future availability or a SAM quota. Account-level entitlement or contractual overrides require account/support evidence. No additional request is required solely for this audit. [Pricing and rate limits](https://dev.meta.ai/docs/pricing-rate-limits).

4. **Licensing and applicable conditions need an account/deployment determination.** Meta's current Model API Terms (last updated October 9, 2026) describe Standard Services and processor terms; the local `@meta-sam/parser` 0.1.0 package contains a distinct SAM License with redistribution conditions. A package license is not the hosted Model API agreement, and published documents alone do not establish which terms, geography, enterprise agreements or redistribution permissions apply to this user's planned deployment. **Follow-up:** record the applicable Meta API terms and geographic/model designation plus parser redistribution obligations for the intended deployment; obtain account-specific confirmation where necessary. This is a scope review, not legal approval. [Model API terms](https://dev.meta.ai/legal/terms-of-service); [parser repository](https://github.com/meta-models/meta-sam).

5. **Evidence and latency are examples, not verified operating limits.** `evidence/sam-live.json`, `evidence/reasoner-live-v4.json`, and `evidence/perception-live.json` report successful synthetic images, actual returned model IDs, sanitized responses and latency samples. They do not establish real-scene segmentation or open-scenario predictive quality, account billing, p95 latency, or the overall G0 decision. The documentation's SAM contract statement that 429 backoff/budget are unimplemented is stale: current `server/provider-policy.js` has shared in-flight, interval, estimated cost and circuit controls.
