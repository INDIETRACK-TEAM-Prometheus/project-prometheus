# Prometheus 구현·수용 Gate 계획

작성: 2026-10-31 KST. 기준 구현 계획: `IMPLEMENTATION_PLAN_20261104.md`. 기존 G0~G5는 SRS 의미를 유지하며 아래 세부 Gate로 증거를 보강한다. 기존 gate-plan.md/CTO_REVIEW의 과거 기록은 삭제하지 않는다.

2026-11-01 감사 보완: [누락·연결·실측 감사](GATE_PROTOCOL_AUDIT_20261101.md)의 A01–A14와 사전 고정 계약을 함께 적용한다. 아래 현재 상태는 초기 평가 상태이며 부분 구현 여부와 구분한다. 문서 추가만으로 통과 상태를 변경하지 않는다.

## 판정 규칙

- 상태: planned → implemented → tested → passed. 외부 의존성 실패는 blocked, 미실행은 not_evaluated, 실행 실패는 failed로 기록한다. planned/failed는 작업 관리 상태이며 SRS 최종 보고에는 원문 상태와 시험 결과를 함께 적는다.
- 현재 신규 Gate는 전부 planned/not_evaluated다. 기존 실호출·258개 회귀 테스트 증거는 해당 범위에서만 재사용한다. 전체 기능 통과로 승격하지 않는다.
- passed에는 commit, 환경, 실제/합성 구분, 명령, 원본 증거 경로·hash, 시각, 기대값/실측값, 실패 수와 판정자가 필요하다. mock·synthetic은 실제 카메라·실제 공급자 Gate를 통과시키지 않는다.
- 수치 중 '제안 기준'은 개발 수용 목표이며 SRS 원문의 수치/실험 규모를 대체하지 않는다. 목표를 맞추려고 실행 후 threshold·표적·실패 분모를 바꾸지 않는다.
- 영상 제출 상태와 SRS 전체 수용 상태를 따로 보고한다. Aria와 연구 GNN이 미완료면 전체 완료로 표기하지 않는다.

독립 정확도 시험은 최소 9개 미사용 표적×3회 제안이며 fixation 안의 많은 프레임을 독립 실험으로 세지 않는다. 사용자1명 성능을 다른 사용자 일반화로 주장하지 않는다. 다음 시선/열린 가설의 성능 목표는 사전 기록하고, 영상에서 그럴듯해 보이는 사례만으로 통과하지 않는다. 구면 재투영 정확도와 실제 gaze 정확도는 별개다.

SRS §20.5 명시 기준을 G2-C/D와 G3-B에 적용한다: 객체 연결 precision ≥90%·coverage ≥60%(동적 3장면·주석 ≥100사건, 최소 객체 폭 조건 포함), glimpse 100–500ms 50건·Recall@3 ≥80% 목표, 이동/가림/재등장 각20사례·기억 Recall@3 ≥90%. 작은 객체/시선 오류/후보 누락을 별도 보고한다. 신규 depth·추론 개선·갱신 age 등의 미정 수치는 감사 문서의 manifest 계약으로 최종 holdout 전에 고정한다.

G2-B에는 비교 프로토콜의 depth 전체 계약(MAE/RMSE/AbsRel/δ1.25·valid coverage, foreground/boundary/gaze ROI, raw metric 출력, artifact 검증)을 적용한다. G3-B는 T07의 시간/위치 오차도 보고한다. G4-C의 기능 통과와 열린 가설 품질 통과를 분리하고, 후자는 독립 2인 blind review 및 사전 품질 기준을 요구한다. G5-C는 T 번호뿐 아니라 개별 SRS 요구 ID별 구현·시험·증거 추적표를 요구한다.

## 증거 폴더와 판정

`docs/evidence/demo-20261104/`에는 비식별 manifest·수치·명령·환경·hash·redacted provider 요약만 보관한다. raw 영상/landmark·교정 원본·원 응답 민감자료는 Git 제외 로컬 디렉터리에 보관하고 manifest로 참조한다. 키·환경 전체 dump를 넣지 않는다.

각 판정 JSON: `gateId,requirementIds,status,implementationStatus,evaluationStatus,commit,testKind,environment,modelVersions,profileHash,startedAtUtc,finishedAtUtc,metrics,thresholds,thresholdVersion,evidencePaths,failures,limitations,reviewer`. 추가 필드는 판정 기록 계약이며 런타임 schema 지원을 의미하지 않는다. 결과 파일 경로는 실제 생성된 파일만 등록한다.

Gate 검토 시 소스 구현·합성 시험·실 API·실 카메라 시험을 확인하고, 기존 통과를 새 변경으로 무효화한 경우 재시험한다. 최종 CTO_REVIEW에는 이 계획의 링크와 실제 판정 요약을 추가한다. 이 계획 작성 자체로 기존 Gate 상태는 변경하지 않는다.
